Da foto do carro ao texto da placa

Um sistema de visão computacional que encontra a placa na foto de um veículo e lê os sete caracteres. Esta página conta como ele foi construído, o que já funciona bem e o que ainda falha.

Nas {{ det.n_teste }} fotos de teste, o detector encontra {{ det.recall }} das placas, e {{ det.precisao }} do que ele marca é de fato uma placa (mAP@0,5 de {{ det.map50 }}).

Como funciona

A leitura acontece em quatro etapas. Cada uma resolve um problema menor e passa o resultado adiante.

  1. Achar a placa

    Um detector YOLO, treinado em {{ det.n_treino }} fotos de veículos brasileiros, marca onde está a placa.

  2. Recortar e achar os caracteres

    A placa é recortada com 8% de folga, e um segundo YOLO localiza cada caractere e já diz qual é (mAP@0,5 de {{ det.chars_map50 }} em {{ det.chars_n_teste }} imagens de teste).

  3. LLLDLDD

    Aplicar a regra do formato

    Na placa Mercosul, cada posição só aceita letra (L) ou dígito (D). Um 0 lido onde deveria haver letra vira O, e um I onde deveria haver número vira 1.

  4. {{ desenhar_placa(etapas.casas, etapas.layout) }}

    Devolver o texto, ou pedir revisão

    Se faltar caractere ou a confiança for baixa, o sistema não arrisca: devolve revisão manual.

O gargalo era a segmentação

A primeira versão seguia o caminho clássico: binarizar a placa, separar os caracteres como manchas e classificar cada uma com uma rede convolucional (CNN). Ela leu {{ rotas[0].car_txt }} dos caracteres e {% if rotas[0].placa == 0 %}nenhuma placa inteira{% else %}{{ rotas[0].placa_txt }} das placas{% endif %}.

O problema não estava na CNN. Depois da binarização, os caracteres encostam uns nos outros e na moldura, e a separação falha antes de a rede ver qualquer coisa. Para testar essa hipótese, mantive a mesma CNN e troquei só a forma de localizar os caracteres por um detector YOLO. Depois deixei o próprio YOLO dizer também qual é o caractere.

Com a mesma CNN, só trocar a localização levou os caracteres certos de {{ rotas[0].car_txt }} para {{ rotas[1].car_txt }}. A rota final, em que o YOLO faz as duas coisas, ficou com {{ leitor.acc_car_pct }} dos caracteres. O código manteve só essa rota.

Onde ainda erra

Em quantas das {{ leitor.n_placas }} placas cada posição sai errada. As posições {{ posicoes.piores }} são as que mais erram.

A regra do formato reduziu os erros de {{ posicoes.total_sem }} para {{ posicoes.total_com }}, somando todas as posições, sem nenhum treino a mais. O que sobra são trocas entre formas parecidas, como 9 e 5, e placas em que o formato (Mercosul ou antigo) foi identificado errado, o que faz a regra trocar o caractere certo pelo errado.

Limites e próximos passos

Hoje o sistema lê corretamente {{ leitor.acertos }} de {{ leitor.n_placas }} placas ({{ leitor.acc_placa }}) e {{ leitor.acc_car }} dos caracteres. As metas do projeto eram 0,80 e 0,95, e ainda não foram atingidas.

Três cuidados ao ler esses números. Com {{ leitor.n_placas }} placas, cada uma vale {{ leitor.peso_placa }} pontos de acurácia, então a medida ainda é grosseira. As placas foram escolhidas entre as maiores e mais legíveis, e não representam fotos noturnas ou placas muito pequenas. E o gabarito foi transcrito à mão, sem usar a regra do formato, para não inflar o resultado.

Privacidade e uso responsável

A placa pode identificar uma pessoa de forma indireta. Este é um projeto acadêmico, sem finalidade de vigilância. Ele usa só bases públicas, nenhuma foto foi tirada por mim, e o sistema devolve apenas o texto da placa: não consulta, guarda nem cruza dados sobre dono, veículo ou local.

Com a acurácia atual, ele não deve ser usado para decisões automáticas sobre pessoas.
